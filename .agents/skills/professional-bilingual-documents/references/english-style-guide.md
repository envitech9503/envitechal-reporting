# Envi Tech AL professional English style guide

## Objective

Client-facing documents must read like professionally edited technical and regulatory documents, not raw application text or AI-generated copy.

## Core style

- Use clear international professional English.
- Prefer concise, direct sentences.
- Preserve technical and regulatory meaning exactly.
- Avoid filler, promotional exaggeration, vague claims, and conversational wording in formal reports.
- Use consistent terminology throughout a document.
- Expand uncommon abbreviations on first use unless the document's approved template defines otherwise.

## Grammar and mechanics

Check every changed client-facing passage for:

- subject-verb agreement;
- articles (`a`, `an`, `the`);
- singular/plural consistency;
- verb tense consistency;
- prepositions;
- punctuation;
- capitalization;
- spacing;
- duplicate words;
- malformed labels;
- awkward sentence fragments;
- unintended ALL CAPS.

## Technical data protection

Do not silently rewrite or normalize:

- test results;
- units;
- standards and methods;
- regulatory citations;
- sample IDs;
- report numbers;
- invoice numbers;
- dates;
- client/legal entity names;
- addresses;
- equipment/model numbers;
- limits and compliance status.

If a source value appears technically wrong, flag it separately instead of fixing it as an English edit.

## Preferred labels

Use stable labels rather than multiple variants inside the same report. Examples:

- Report No.
- Reporting Date
- Client
- Address
- Attention
- Sample ID
- Sample Description
- Sample Type
- Sample Collected By
- Sample Collection Date
- Date of Analysis
- Test Description
- Test Method
- Result
- Unit
- Regulatory Limit
- Remarks

Existing approved client templates may override these labels.

## Dates and numbers

- Keep one date style within a document.
- Do not mix `01/08/2026`, `1 Aug 2026`, and `August 1, 2026` without a template reason.
- Keep decimal precision consistent with the analytical method/reporting rule.
- Use a space between a numeric value and most scientific units where appropriate, except symbols conventionally attached to the number (for example `%`).
- Do not modify scientific notation or inequality symbols merely for typography.

## Headings

- Use a consistent hierarchy.
- Avoid sentence-ending punctuation in short headings.
- Use title case or sentence case consistently according to the template.
- Do not use decorative capitalization as a substitute for hierarchy.

## Final editorial gate

Before completion, read the document as a client, auditor, regulator, and laboratory reviewer would. Fix language defects without changing the underlying facts.
